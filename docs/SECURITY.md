# VOXY — security notes

Baseline: **OWASP ASVS** (used as a checklist for design and testing, not as a certification claim).
This document lists the controls that exist and what was tested. It does not claim the system is "secure",
"compliant" or free of vulnerabilities; it has not had an independent penetration test or audit.

## Architecture

`browser → Fastify (headers, request ID, body limit, global rate limit, CSRF) → authn (session) → authz (central policy) → business logic → PostgreSQL → Stripe / SMTP`.
The browser is never a source of truth. It receives only: its session cookie (HttpOnly), an in-memory CSRF token,
and the allow-listed output of `GET /api/config/public`. Role, user id, plan and entitlements are always derived from the server-side session and database.

## Controls

| Area          | Control                                                                                                                                                                                                                                                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Passwords     | Argon2id (m=19456 KiB, t=2, p=1), 12–128 chars, small deny-list of very common passwords, no composition rules. Not checked against a breach corpus (gap).                                                                                                                                                                                  |
| Sessions      | 256-bit random token, only SHA-256 stored. Cookie `__Host-voxy_session` (HttpOnly, Secure, SameSite=Strict, Path=/) over HTTPS. Rotation on login, password change and re-auth. Idle timeout (default 7 d) and absolute timeout (default 30 d). Logout, revoke one, logout everywhere.                                                      |
| CSRF          | Unsafe `/api/*` requests need: `Origin` equal to `APP_URL` (or `Sec-Fetch-Site: same-origin`), `Content-Type: application/json`, and `X-CSRF-Token` = HMAC(appSecret, sessionId). SameSite=Strict is defence in depth, not the only control.                                                                                                |
| Brute force   | Login attempts are **reserved atomically before** the slow hash: per-IP (40/15 min), per-account+IP (5/15 min), per-account (20/h). Per-account budget is exempted for a browser holding the signed device cookie, so an attacker spraying passwords cannot lock the owner out. Reset/verify/reauth/change-password have their own budgets. |
| Enumeration   | Register, login, forgot-password and resend-verification give identical responses and comparable timing (dummy hash) whether or not the account exists.                                                                                                                                                                                     |
| Tokens        | Email-verification (24 h) and reset (1 h) tokens: random, hashed at rest, single-use (atomic consume), newest supersedes older, delivered in the URL **fragment** (never sent to servers/Referer) and scrubbed from the address bar.                                                                                                        |
| Authorization | `server/authz/policy.ts`; ownership enforced in SQL (`user_id = caller`); foreign resources return 404; admin cannot act on self; role changes take effect immediately; DB CHECK constraints on role/status.                                                                                                                                |
| Billing       | Price IDs resolved server-side; webhook signature verified on the raw body; events deduplicated in `webhook_events`; stale/out-of-order events ignored; entitlements recomputed from stored subscription state (grace period for `past_due`); fail-closed if billing is half-configured.                                                    |
| Headers       | CSP built from VOXY's real resources (`default-src 'self'`, no `unsafe-inline`/`unsafe-eval`, `worker-src blob:` for three.js, `frame-ancestors 'none'`, `base-uri 'none'`), HSTS, nosniff, Referrer-Policy, Permissions-Policy, COOP/CORP, no CORS grants.                                                                                 |
| Input         | zod `strictObject` schemas on every body/param, 32 KB body limit (1 MB raw only on the webhook), parameterised SQL everywhere, no user-supplied URLs fetched (SSRF surface is nil by design), no redirects from user input.                                                                                                                 |
| Client IP     | Trusted-proxy hop count (`TRUST_PROXY_HOPS`); forged leading `X-Forwarded-For` entries are not trusted. A startup warning fires if it is 0 in a hardened environment.                                                                                                                                                                       |
| Errors        | Envelope `{ok:false,error:{code,message,requestId}}`. Stack traces, SQL, paths and env values never reach clients; request ID is shown so support can find the server log. Handler timeout (20 s) → 503.                                                                                                                                    |
| Logging       | Structured JSON (pino), request IDs, redaction of auth headers/cookies; tests assert that passwords, tokens, cookies and webhook secrets do not appear in logs. Security events are also stored per user and shown on the account page; admin actions go to `audit_events`.                                                                 |
| Config        | zod-validated env; staging/production refuse to start without `APP_SECRET`, real Postgres, SMTP, company info, https `APP_URL`. Browser bundle contains no env values (checked by `verify:build`).                                                                                                                                          |
| Supply chain  | Lockfile, `npm audit` in CI (high+), repo secret scan + gitleaks, ESLint security rules, Dockerfile runs as non-root with prod deps only.                                                                                                                                                                                                   |

## Vulnerabilities found and fixed during development (reproduce → root cause → fix → regression test)

| ID    | Finding                                                                                                                                                                                       | Root cause                                                                                | Fix + test                                                                                           |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| REG-1 | Per-IP rate limits could be evaded by sending a forged `X-Forwarded-For`.                                                                                                                     | Trusted-proxy callback used `hop <= hops`, so a client-supplied entry became `req.ip`.    | `hop < hops`; `tests/server/regressions.test.ts`.                                                    |
| REG-2 | Parallel password guesses all slipped under the login limit.                                                                                                                                  | Check-then-act: limiter peeked, then counted failures only after the slow hash.           | Atomic reserve-before-verify, release on success; same for reauth/change-password; regression tests. |
| REG-3 | After "Delete account" the UI stayed on the signed-in account view.                                                                                                                           | `queryClient.clear()` detached mounted session observers, so the sign-out never rendered. | Remove user-scoped queries and set the session query in place; `tests/client/pages.test.tsx`.        |
| —     | Dev server crashed on first boot (PGlite data dir missing); startup failure printed a raw stack. Both fixed (`pglite.ts` mkdir; concise fatal log). Found by running the build, not by tests. | —                                                                                         | —                                                                                                    |

## What was tested

`npm test` runs **~190 automated tests** (server: auth, authz, billing, security, reliability, regressions; client: API client, redirects/tokens, pages). Server tests run against real PostgreSQL semantics (PGlite) with an injected clock and fake mail/billing providers. In addition, real headless-Chromium flows were executed against the built server: register → email link → verify → wrong password → login → hardened-cookie check → change password → second device → logout everywhere → forgot/reset → waitlist → legal pages → 404 with zero API calls → account deletion.

## Known gaps and residual risk (read before launch)

- **Not run against real services in this environment:** a real PostgreSQL server (CI job `postgres-smoke` exists but had not run), real Stripe API calls (webhooks are tested with correctly signed synthetic payloads; checkout/portal use a fake provider in tests), real SMTP delivery, the Docker image build, and the GitHub Actions workflow itself.
- **3D performance was measured only under software rendering.** Adaptive tiers, pausing and disposal are implemented, but real-GPU frame rates (and how the orb trails look at 60 fps) must be checked on target devices.
- No MFA, no breached-password lookup, no CAPTCHA, no WAF/DDoS protection (use the edge for volumetric attacks). The in-process global limiter is per instance; auth limiters are stored in PostgreSQL and shared.
- No client-side error reporting endpoint (render errors show a safe screen but are not reported); no external uptime/metrics/alerting is wired up.
- Legal pages are structured drafts. Refund terms, retention, legal bases, liability and governing law must be written and reviewed by the business/legal owner. Marketing claims on the landing page (on-device encryption, zero-latency voice, "private by design", "Bloom") need owner verification.
- Dependency audit was clean on the day of writing; it will not stay clean. Keep Dependabot/renovate and the CI audit gate on.
- Report vulnerabilities to `SECURITY_CONTACT_EMAIL` (configure it); no bug-bounty or disclosure policy has been written.
